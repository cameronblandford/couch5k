# Couch5k on Apple Watch

Date: 2026-10-13. watchOS support for the whole app.

## What it is

A watch app, `Couch5kWatch` (bundle `com.example.Couch5k.watchkitapp`), that is installed with the iPhone app.
It runs a full session with no phone in reach: the plan, the warmup drills, the run with its cues, the summary, and the save to Health.

## Decisions

- **The phone owns the history.** The watch has no SwiftData store. The phone sends a short list of all its runs
  (`SyncContext`, WatchConnectivity application context). The watch finds the next session from that list with the
  same rule as the phone: the session after the furthest one completed.
- **A watch run goes to the phone as a `RunPayload`** (`transferUserInfo`, which the system delivers later if the phone
  is not in reach). The phone makes a `CompletedRun` with the same id, so a run that arrives twice is stored once.
  The watch keeps its copy until the phone lists the id in `received`. A run deleted on the phone stays deleted.
- **The same engine and the same figures.** The watch target compiles the phone's `Plan`, `Engine`, `Audio`,
  `Location`, `Health`, `SegmentRecorder`, `Settings`, and `Theme` files. Distance is from GPS with the same filters,
  one Health distance sample for each interval, so a watch run and a phone run compare.
- **The Health workout is live on the watch** (`LiveWorkout`). It keeps the app in work with the wrist down, it gives
  the heart rate, and it survives a crash (the same recovery file and alert as on the phone).
- **Cues:** a tap on the wrist for each cue (run and walk feel different), plus the chimes and the voice. The voice
  and the chimes have switches on the watch; the taps are always on.
- **Screens:** Home (next run, Start), The plan (each session can be started), warmup, run (three pages: controls,
  interval, figures), summary (Save or Discard), History (read only), Settings.

## Not in this version

- Progress charts and the route map on the watch. They are on the phone.
- Mark a session as done, and delete a run, on the watch. Do these on the phone.
- A view on the watch of a run that the phone records (mirroring), a complication, and a Smart Stack widget.
- The pace comparison with earlier runs (the faster and slower pills).

## Test

`scripts/test.sh` runs the unit tests, including `WatchSyncTests` for the payload and the history rules.
`scripts/watch-uitest.sh [folder]` taps through the watch app in a watch simulator (a full fast session, an early end,
the plan and the settings) and can keep the screenshots. `scripts/watch-sim.sh [arguments]` starts the app there.
The launch argument `-noprompts` keeps Health and location off, because nothing can tap a permission prompt in the simulator.
So the Health workout, the heart rate, GPS on the watch, the taps on the wrist, the sound, and the link to the phone
are tested only on a real watch.
